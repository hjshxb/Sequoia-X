# Sequoia-X: 王者回归 | The King Returns

> A 股量化选股系统 V2 | A-Share Quantitative Stock Selection System V2

---

## 简介 | Introduction

Sequoia-X V2 是面向 A 股市场的量化选股系统，基于现代 Python 工程化标准从零重构。
系统以 OOP 架构、向量化计算和增量数据更新为核心设计原则，每日收盘后自动选股并推送至飞书群。

数据层使用 [baostock](http://baostock.com)（免费、无需注册、无限流）拉取历史及增量日 K 数据（后复权），
存储于本地 SQLite，彻底规避东方财富反爬问题。

---

## 运行模式

```bash
python main.py                # 日常模式：增量补数据 + 跑策略 + 飞书推送 + 生成本地HTML报告
python main.py --no-push      # 只跑策略并生成本地HTML报告，跳过飞书推送
python main.py --workers 4    # 指定增量同步的并发进程数（默认 1，即单进程串行）
python main.py --backfill     # 回填模式：全市场历史K线一次性灌入
```

## 股票池精筛 | Universe Filters

所有策略在返回选股结果前，都会统一经过 `UniverseFilter` 精筛。
共 **5 个维度**，全部可选，在 `.env` 中配置；**留空即表示该维度不参与过滤**。
五个维度都不配置时，**完全不产生网络请求**。

### 1) 估值

| 配置项 | 含义 | 单位 |
|---|---|---|
| `MIN_MARKET_CAP` / `MAX_MARKET_CAP` | 流通市值区间 | 亿元 |
| `MIN_PE` / `MAX_PE` | 市盈率(TTM) 区间 | 倍 |
| `MIN_PB` / `MAX_PB` | 市净率区间 | 倍 |

```bash
# 只看 100 亿以上流通盘，且排除亏损股
MIN_MARKET_CAP=100
MIN_PE=0
```

### 2) 流动性

| 配置项 | 含义 | 单位 | 数据来源 |
|---|---|---|---|
| `MIN_TURNOVER` | 成交额下限 | 亿元 | **本地 SQLite**（零网络开销） |

### 3) 技术面

| 配置项 | 含义 | 单位 |
|---|---|---|
| `MIN_TURN` / `MAX_TURN` | 换手率区间 | % |

换手率可用于剔除「过于冷门」（无人关注）与「过热」（追高）的票：

```bash
MIN_TURN=2      # 换手率 >= 2%
MAX_TURN=20     # 换手率 <= 20%
```

### 4) 行业

| 配置项 | 含义 |
|---|---|
| `INCLUDE_INDUSTRIES` | 白名单，逗号分隔关键词；非空时只保留**命中任一关键词**的股票 |
| `EXCLUDE_INDUSTRIES` | 黑名单，逗号分隔关键词；命中的一律排除 |

关键词按**子串匹配**行业名，不必写全称（中英文逗号均可）：

```bash
INCLUDE_INDUSTRIES=电子,软件,医药   # 只保留泛科技 / 医药
EXCLUDE_INDUSTRIES=房地产,银行      # 排除地产与银行
```

> 实测提示：**白名单比黑名单有效得多**。因为策略本身已天然偏向科技制造，
> 「排除房地产/银行/金融/建筑」往往只能剔掉个位数股票。

### 5) 筹码集中度

| 配置项 | 含义 | 单位 | 默认 |
|---|---|---|---|
| `MIN_TOP10_FREE_HOLDING` / `MAX_TOP10_FREE_HOLDING` | 前十大流通股东合计持股占**流通股**比例区间 | % | 不启用 |
| `HOLDER_REPORT_DATE` | 指定股东数据报告期（`YYYY-MM-DD` 或 `YYYYMMDD`） | — | 空 = 自动取最新已披露季末 |
| `HOLDER_CACHE_DIR` | 股东数据缓存目录 | — | `data/cache` |

数据取自东方财富**全市场**接口（`RPT_F10_EH_FREEHOLDERS`），一次分页拉全市场，
按报告期落盘缓存 —— 一年只更新 4 次，命中缓存后零网络开销。
（baostock **没有**股东数据接口，逐只取数需 25 分钟以上，故走东财。）

```bash
MIN_TOP10_FREE_HOLDING=30    # 只保留前十大流通股东合计持股 >= 30% 的股票
```

> 实测提示：全市场该指标**中位数约 47%**，`>=30%` 近乎不筛（实测只剔掉约 5%）。
> 想真正收敛，建议 `50~60`。

判定规则与其它维度一致，但有一处**刻意的不对称**：
单只股票在该报告期**查不到**持股数据时 ——
配置了下限则**剔除**（宁可漏掉，不可放进未知筹码的票），
只配置上限则**放行**（上限是「排除过于集中」的负面条件，缺少数据不构成排除理由）。

### 实战：从 92 只收敛到 38 只

以某日实跑为例（7 个策略合计去重后 92 只），各档位的实际收敛效果：

| 档位 | 配置 | 剩余 |
|---|---|---|
| 温和 | `MIN_TURNOVER=5` + `MIN_TURN=1` `MAX_TURN=15` | 70 只 |
| 平衡 | 温和档 + `MAX_PB=10` | 42 只 |
| 聚焦科技（换手 2~10） | `MIN_TURNOVER=5` + `MIN_TURN=2` `MAX_TURN=10` + `INCLUDE_INDUSTRIES=电子,软件,医药` | 32 只 |
| **聚焦科技（换手 2~20）** | `MIN_TURNOVER=5` + `MIN_TURN=2` `MAX_TURN=20` + `INCLUDE_INDUSTRIES=电子,软件,医药` | **38 只** |

> 换手率上限从 10% 放宽到 20% 后多纳入 6 只（华天科技、星网锐捷、崇达技术、
> 东田微、嘉元科技、盛合晶微），都是换手偏活跃的科技股。

### 口径与行为说明

- **市值口径**：流通市值 = 不复权收盘价 × 流通股本，其中
  `流通股本 = 成交量 / (换手率% / 100)`。与 `TurtleTradeStrategy` 的市值排序口径一致。
- **市盈率口径**：baostock `peTTM`（滚动市盈率）。亏损股该字段为空，
  因此在配置了市盈率过滤时会被判定为不通过；`MIN_PE=0` 亦可排除负市盈率。
- **判定规则**：区间为闭区间（含边界）。**单只股票**某个指标缺失，视为不通过该维度。
- **数据来源**：估值 / 技术面来自 baostock 不复权日线（只查候选股，非全市场）；
  成交额来自本地库；行业来自 `query_stock_industry()` 整市场一次请求。
  均有进程内缓存，同一次运行中多个策略共享，不会重复请求。
- **容错（重要）**：若某个维度的数据源**整体**拉取失败（网络 / 接口异常），
  只跳过**该维度**并记 ERROR，其余维度照常生效 —— 避免单个数据源故障
  把候选股全部误杀成空结果。

## 本地 HTML 报告 | HTML Report

日常模式跑完所有策略后，会自动生成一份**本地单文件 HTML 报告**，
按策略分块列出选出的股票，支持页内搜索，双击即可用浏览器打开，
不需要任何网络或额外依赖。

```bash
python main.py
# → reports/stock_report_2026-09-19.html
```

| 配置项 | 含义 | 默认值 |
|---|---|---|
| `REPORT_ENABLED` | 是否生成 HTML 报告 | `true` |
| `REPORT_DIR` | 报告输出目录 | `reports` |

报告特性：

- **按策略分块**：每个策略一张卡片，带命中数量徽标与板块概览；
  无结果的策略也会保留卡片并标注
- **按上市板块分组排序**：每张卡片内部按 `主板 → 创业板 → 科创板 → 北交所` 分组，
  每组一行小标题（含只数），组内按代码升序
- **列**：`代码 / 名称 / 板块 / 行业`；若精筛已启用，还会展示
  **`市值(亿) / 换手率 / PE(TTM)`** 三列（缺数据显示为「—」）
- **页首概览**：日期、策略命中数、合计选出数，以及当前生效的精筛条件
- **页内搜索**：即时过滤代码 / 名称 / 行业 / 板块，自动隐藏无匹配的策略卡片与空分组标题
- **单文件自包含**：CSS/JS 全部内联，便于归档、分享或直接拷给别人

### 板块判定规则

板块由**代码前缀**本地判定，不联网、零开销：

| 板块 | 代码前缀 | 涨跌幅 |
|---|---|---|
| 主板 | 600 / 601 / 603 / 605（沪）、000 / 001 / 002 / 003（深） | 10% |
| 创业板 | 300 / 301 | 20% |
| 科创板 | 688 / 689 | 20% |
| 北交所 | 43 / 83 / 87 / 88 / 920 | 30% |

名称与行业来自 baostock `query_stock_industry()`，**整市场一次请求**并做进程内缓存。
行业会去掉证监会分类前缀（`J66货币金融服务` → `货币金融服务`）。

> 报告生成失败不影响主流程（会记 ERROR 日志），也不依赖飞书是否配置。
> 展示用的市值 / 换手率 / PE 复用精筛阶段已缓存的指标，**通常不产生额外网络请求**。

## 快速开始 | Quick Start

### 环境要求

- Python >= 3.10

### 1. 安装依赖

```bash
# 推荐使用 uv（快速包管理器）
uv sync

# 或者 pip
pip install .
```

### 2. 配置环境变量

```bash
cp .env.example .env
# 编辑 .env，填写飞书 Webhook URL
```

### 3. 首次回填历史数据

```bash
python main.py --backfill
```

约 12 分钟完成 ~5200 只 A 股历史后复权日 K 数据回填。

### 4. 日常运行

```bash
python main.py
```

建议配合 crontab 每个交易日收盘后自动执行：

```cron
15 19 * * 1-5 cd /root/Sequoia-X && .venv/bin/python main.py >> log.txt 2>&1
```

## 数据说明

- **数据源**：[baostock](http://baostock.com)（免费、无需注册、无限流）
- **复权方式**：后复权（hfq）— 历史价格不变，适合增量存储，避免除权导致数据错乱
- **存储**：本地 SQLite（`data/sequoia_v2.db`），可直接拷贝到其他机器使用
- **日常增量**：通过 baostock 拉取，并发进程数由 `SYNC_WORKERS`（或 `--workers`）控制，
  **默认 1（单进程串行）**；调大后 2~3 分钟可完成全市场更新
- **精筛指标**：流通市值 / 市盈率(TTM) / 市净率 / 换手率按需从 baostock 不复权日线获取，
  不入库、不落盘（仅进程内缓存）；成交额取自本地库

> ⚠️ **不要把 `SYNC_WORKERS` 调大后再全市场跑**。baostock 对同一客户端的并发登录有风控，
> 实测「5221 只 × 8 进程」的重试风暴会直接换来 `10001011 黑名单用户`，
> 之后**连 login 都要 1.5~2 分钟才超时**（`10002007 网络接收错误`），恢复期很长。
> 遇到黑名单时**切勿反复重试**，越试越难恢复；先停手，隔一段时间再单进程跑。
> 排障可先执行 `python -m logs.probe_baostock`。

> 注：`--backfill` 是单线程逐只拉取，耗时高度依赖到 baostock 的网络状况。
> 网络较慢时可能远超 12 分钟（实测有约 15 只/分钟、全量需数小时的情况），
> 属正常现象；中断后重跑会自动跳过已入库的股票，可直接续传。
